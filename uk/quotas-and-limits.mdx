title: "Квоти та ліміти"
description: "Ліміти Memory MCP, умови paid plan і що враховується в квотах retrieve."
---

Memory MCP застосовує ліміти на виклики `retrieve_memory` для кожного акаунта. Доступ потребує активного **paid plan** (підписка Memory MCP).

## Що враховується

**У місячний ліміт retrieve:** успішні `tools/call` з `name: retrieve_memory` на `POST /v1/mcp/memory` — лише коли retrieval завершується успішно.

**У погодинний burst-ліміт:** кожна автентифікована спроба `retrieve_memory` після перевірки entitlement (включно із заблокованими викликами).

**Логуються, але не зменшують місячну квоту:** заблоковані виклики після автентифікації (quota exceeded, entitlement blocked, invalid arguments тощо) з’являються в **[Request Log](https://pam.harmix.ai/request-log)**, але не зменшують місячний retrieve allowance.

**Не враховуються взагалі:**

- `initialize`, `initialized`, `tools/list`, `resources/list`, `prompts/list`
- REST-виклики Developer API (`/v1/dev/*`)

## Ліміти paid plan

Memory MCP пропонується в одному **paid plan**. Типові ліміти:

| Ліміт | Значення |
|-------|----------|
| Успішні виклики `retrieve_memory` | **1 000** за billing period |
| Погодинний burst | **100** викликів на UTC годину |
| Підключені OAuth memory sources | **1** |

Кожен успішний retrieval використовує один retrieve request із місячного allowance. Handshake і discovery методи безкоштовні.

## Розклад скидання

| Вікно | Скидання |
|-------|----------|
| Погодинний burst | Початок кожної UTC години |
| Місячний retrieve allowance | ~32 дні після останнього платежу за підписку (`reset_at` у Usage UI та `GET /v1/dev/mcp-config`) |

## Перевірка підписки

`entitlement_required` повертається, коли Memory MCP недоступний на акаунті — наприклад, немає активного paid plan, Memory MCP не увімкнено, підписка неактивна або на PAM-акаунті не залишилось chat credits.

Оновіть або поновіть підписку на **[Setup](https://pam.harmix.ai/setup)**, щоб продовжити.

## Попередження про наближення до ліміту

Сторінка **[Usage](https://pam.harmix.ai/usage)** у застосунку PAM показує статус квоти:

| Статус | Значення |
|--------|----------|
| `ok` | У межах ліміту |
| `near_limit` | Понад 80% місячного retrieve limit |
| `limited` | Місячний retrieve limit досягнуто |
| `entitlement_required` | Memory MCP недоступний на акаунті |

Актуальну квоту перевірте на **Usage** або через `GET /v1/dev/mcp-config` (див. [Налаштування та ключі](/uk/setup-and-keys)).

## Приклад: відповідь quota_exceeded

Помилка на рівні інструменту (HTTP 200, `isError: true`):

```json
{
  "content": [
    {
      "type": "text",
      "text": "Rate limit exceeded. Please try again later."
    }
  ],
  "structuredContent": {
    "status": "error",
    "error_code": "quota_exceeded",
    "error_message": "Rate limit exceeded. Please try again later."
  },
  "isError": true
}
```

## Історія запитів

Кожна спроба `retrieve_memory` зберігає повний prompt і відповідь для перегляду в **[Request Log](https://pam.harmix.ai/request-log)** та через `GET /v1/dev/mcp-requests`.

<Warning>
  `quota_exceeded` стосується лише `retrieve_memory` через `tools/call`, а не handshake-методів чи REST Developer API.
</Warning>
